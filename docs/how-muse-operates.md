# このサイトで Muse がしていること

このサイト「ポちの中国地方おでかけガイド」は、人間（運営者：ポち）とAIエージェント「Muse」（Meta製）の分担で作られ、運用されています。このドキュメントは、Muse が何をし、人間が何を決めているのかを、note 記事などの素材として使えるよう正直にまとめたものです。

- リポジトリ: https://github.com/aegisfleet/chugoku-odekake-guide
- 公開サイト: https://aegisfleet.github.io/chugoku-odekake-guide/

## 全体像

```
Instagram / Threads の公開投稿
  → 候補の収集と選定（Muse）
  → 検証ゲート：公式情報・Googleマップとの照合（Muse）
  → データ作成：1件1ファイルの YAML（Muse）
  → Hugo でビルド → GitHub Pages へ自動公開
  → 日次・週次・月次の定期運用で鮮度を維持（Muse、スケジュール実行）
  → 結果はチャットで運営者へ事後報告
```

方針の決定（ジャンル設計、運用ルール、公開の可否）は人間が行い、それ以外の実務の大部分を Muse が担っています。

## Muse がしていること

### 1. 候補の収集と選定

- Instagram / Threads で中国地方（鳥取・島根・岡山・広島・山口）のおでかけスポットを紹介する公開投稿を検索し、候補を集めます。
- 候補はプールで管理し、県とジャンルのローテーションで偏らないよう選定します。選定履歴も記録し、重複を避けます。
- 複数のお店をまとめた紹介投稿は対象外とし、主役が1件に定まる投稿だけを出典にします。

### 2. 検証ゲート（掲載前の照合）

出典投稿をそのまま信じず、掲載前に次を照合します。ここを通らないものは掲載しません。

- 投稿に書かれたエリア・住所のヒントと、Googleマップ上の施設情報が一致すること
- 同名の別施設・別支店を取り違えていないこと
- 閉店・休館していないこと（公式情報で確認）
- Googleマップにピン（施設登録）があること

実際に起きた訂正例：あるカフェのエリアが地図サービス側の表記で「佐伯区」となっていましたが、公式アカウントのプロフィールと出典投稿の両方が「西区」で一致したため、西区として登録し直しました。地図サービスの情報を鵜呑みにしないための照合です。

### 3. データ作成

- 掲載情報は `data/places/<slug>.yaml`（1件1ファイル）に構造化して保存します。Markdown への変換はしません。
- 出典投稿は、詳細ページに Instagram の公式埋め込みで表示します。写真のファイル自体はサイトに置かない（転載しない）ための仕組みです。
- 関連投稿は複数集めて「よく紹介されるもの」（メニューや見どころ）を集計します。いいね数は取得日つきのスナップショットとして扱い、その旨を明示します。
- 公式アカウント・公式サイトの有無も確認して記録します（無い場合は「公式サイトのみ」など、確認できた範囲だけを載せます）。

### 4. ビルドと公開

- Hugo（extended 0.167.0）でビルドし、GitHub Actions 経由で GitHub Pages に公開します。
- ビルドのたびに、内部リンクがすべてサイトのパス（`/chugoku-odekake-guide/`）で始まっているかを全数検査します。プロジェクトPagesのサブパスでリンクが壊れる問題を実際に踏んだための決まりです。

### 5. 表示まわり・計測の実装

- イベントの終了表示（開催最終日の翌日から「終了」）、開催中・終了間近のバッジ、お知らせ欄など、情報の鮮度が目で見て分かる表示を実装しています。
- ページの更新日付は、情報の区間ごとに分け
